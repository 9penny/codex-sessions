# Codex Sessions v0.2.2

v0.2.2 is a privacy hardening patch for the local derived session index.

## Fixed

- New `csessions` data directories are created with mode `0700`.
- `sessions.db` and its SQLite `-wal` and `-shm` sidecars use mode `0600`.
- Opening an index created by v0.2.1 automatically tightens its existing directory and file
  permissions. No native Codex JSONL or indexed content is changed.
- A custom database path still gets private database and sidecar files, while an unrelated
  pre-existing parent directory is not chmodded by the library.

This matters on multi-user Linux/WSL systems: v0.2.1 could create the redacted derived index as
world-readable under a world-traversable application data directory, depending on the user's
umask. The index excludes reasoning and tool data and remains disposable, but it still contains
redacted conversation text and local paths, so owner-only access is the correct default.

## Upgrade

Install v0.2.2, then run any command that opens the index, such as `csessions reindex`. The
permission migration happens automatically. Deleting `sessions.db` is unnecessary.

All v0.2.1 enrichment, search, resume, redaction, and network-boundary behavior is unchanged. See
the [v0.2.1 notes](V0.2-RELEASE-NOTES.md) for the full feature release.
