# Optional AI Enrichment

AI enrichment is an explicit, optional v0.2 feature. Normal `resume`, `search`, `reindex`, TUI,
version, and help workflows remain local-only and do not construct an AI client.

## Privacy boundary

`csessions enrich` opens a candidate's indexed native Codex JSONL and structurally selects only
user and assistant text. Reasoning, tool calls, tool arguments, tool output, native paths, session
IDs, project paths, environment data, and other record metadata are excluded before redaction.
Detected secrets are replaced with typed `[REDACTED:...]` placeholders. A parse, file-fingerprint,
or redaction failure stops the run without sending that session.

Live requests use a Responses-compatible endpoint with `store: false`, no tools, and a strict JSON
schema. `store: false` does not override an API provider's abuse-monitoring retention policy. The
command therefore requires `--yes` and prints that boundary before its first live request.

Only the validated title, summary, tags, model, prompt version, aggregate usage, timestamp, and
source fingerprint are written to the disposable `sessions.db`. Outbound conversation text and API
credentials are not persisted there. Native JSONL is never modified.

## Configuration

The default model is `gpt-5.4-mini`, selected by the checked-in synthetic evaluation. Override it
with `CSESSIONS_OPENAI_MODEL` or `--model`. API credentials have no command-line flag.

Use environment variables:

```bash
export CSESSIONS_OPENAI_API_KEY='...'
export CSESSIONS_OPENAI_BASE_URL='https://api.openai.com/v1' # optional
export CSESSIONS_OPENAI_MODEL='gpt-5.4-mini'                 # optional
```

Or create `~/.config/csessions/ai.toml` (respecting `XDG_CONFIG_HOME`) with mode `0600`:

```toml
api_key = "..."
base_url = "https://api.openai.com/v1"
model = "gpt-5.4-mini"
```

Environment variables override the file. Remote endpoints must use HTTPS; credentials, queries,
and fragments in endpoint URLs are rejected, as are redirects outside the configured origin.

## Safe workflow

Enrichment defaults to the project containing the current working directory. Use `--project PATH`
to choose another project, or `--all` to explicitly select the global session library. `--all` and
`--project` cannot be combined. The command prints its resolved scope before any live confirmation.

First run the entirely local preview for the current project:

```bash
csessions enrich --dry-run --limit 10
```

It prints only aggregate candidate and conservative input-budget counts. It makes zero requests and
writes no AI metadata. Then explicitly authorize a bounded live batch:

```bash
csessions enrich --yes --limit 10 \
  --max-input-tokens 2000 \
  --max-total-input-tokens 10000 \
  --max-output-tokens 256
```

Choose a different project or the global library explicitly:

```zsh
csessions enrich --project ~/Projects/example --yes --limit 10
csessions enrich --all --yes --limit 10
```

The input estimate uses UTF-8 bytes as a tokenizer-independent upper bound. Oversized sessions keep
their opening intent and recent tail after redaction. Successful rows commit one at a time, so an
interrupted rerun skips unchanged completed sessions. `--force` regenerates current rows; Ctrl+C
cancels further work.

Use `csessions enrich models` to list only the model IDs exposed by the configured endpoint.
