# Codex Sessions v0.1 Implementation Plan

Updated: 2026-08-15

## Objective

Deliver a safe, local-only, Codex-only terminal session browser suitable for daily use on Linux and WSL over SSH. The native Codex JSONL files remain authoritative and are never mutated.

The v0.1 release does not include AI enrichment. Its job is to establish privacy, correctness, search, preview, resume, and new-session foundations that v0.2 can safely build on.

## Locked product decisions

- Product name: `Codex Sessions`
- Command: `csessions`
- Supported environment: Linux and WSL, including SSH terminals
- Source of truth: native `~/.codex/sessions` JSONL
- Derived data: disposable SQLite index containing redacted text only
- Default visibility: interactive sessions only
- Hidden by default: subagent, `exec`, empty, unknown-source, and archived sessions
- Raw transcript access: on-demand from native JSONL, masked by default, never cached or logged
- Network policy: no outbound connection in v0.1
- Dependency policy: prefer the Go standard library and existing dependencies; add no dependency without an explicit decision

## Completed foundation

The following changes are merged into `dev`:

- Stage 0 fork bootstrap and upstream push protection
- Codex source classification with default filtering for subagent, `exec`, and unknown sessions
- Resume from the session's recorded project directory, including the actual Codex child process cwd
- Conversation-only indexing that excludes thinking, tool parameters, and tool output
- Fail-closed secret redaction before searchable text is persisted
- Reindex version bump so legacy unsafe bodies are replaced

## Execution order

Each numbered item is an independent branch and pull request. Do not combine adjacent items merely because they touch the same package; the separation is the rollback boundary.

Implementation status:

- [x] 1. Enforce the local-only runtime boundary

### 1. Enforce the local-only runtime boundary

Disable all inherited outbound and account behavior before adding more user-facing functionality.

Scope:

- Remove PostHog initialization and event transmission from executable paths.
- Remove OpenTelemetry initialization, prompt spans, metrics export, flags, and configuration.
- Remove cloud login, logout, sync, cloud blending, and account prompts from the command and TUI surfaces.
- Disable automatic version checks and remote badges or notices.
- Ensure ordinary startup, reindex, search, preview, resume, and exit perform no network connection.
- Keep dead packages temporarily if deleting them would make this PR difficult to review; remove them in step 6.

Verification:

- Add a subprocess or injected-dial regression test that observes zero outbound connection attempts for supported commands.
- Confirm prompt text, project paths, session IDs, and device identifiers have no outbound path.
- Run the complete Go suite; the inherited telemetry closed-port test should disappear with the removed runtime.

Exit condition: v0.1 commands are local-only by construction, not merely by default configuration.

### 2. Establish product identity and XDG storage

Move away from inherited SpecStory naming and storage before users create a lasting Codex Sessions database.

Scope:

- Build the executable as `csessions` and update command help and user-facing names.
- Use `~/.config/csessions` for configuration.
- Use `~/.local/share/csessions/sessions.db` for the derived index.
- Use `~/.cache/csessions` for disposable cache data.
- Respect `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_CACHE_HOME` when set.
- Do not import the inherited `.specstory/sessions.db`; rebuild safely from native JSONL.
- Keep all paths overrideable in tests without changing the real home directory.

Verification:

- Table-driven path tests cover defaults, XDG overrides, missing variables, and WSL paths.
- An isolated-home integration test proves no `.specstory` directory is created.
- The built binary reports the Codex Sessions name and version.

Exit condition: a clean invocation writes only to the documented XDG locations.

### 3. Replace indexed preview with an on-demand native preview

The FTS body is for discovery only. It must not be treated as the canonical or complete transcript preview.

Scope:

- Parse the selected native JSONL file only when opening or refreshing preview.
- Render the complete supported conversation without storing another raw transcript copy.
- Mask detected secrets by default before text reaches the TUI model.
- Add an uppercase `R` action that reveals the current preview in memory only.
- Clear revealed content when selection, mode, or process lifetime changes.
- Never write revealed content to SQLite, cache, debug output, analytics, logs, panic reports, or clipboard automatically.
- Fail closed with a clear blocked-preview message if redaction cannot initialize or the native path is invalid.

Verification:

- Synthetic JSONL tests cover user, assistant, reasoning, tool calls, tool output, malformed lines, and large sessions.
- A sentinel secret is absent from the default rendered model, database, logs, and cache.
- Reveal tests prove the sentinel exists only in the active in-memory preview and disappears on navigation.
- Preview tests do not use real session content.

Exit condition: preview is complete enough for session recognition while raw content remains ephemeral and masked by default.

### 4. Add bilingual full-text search

Preserve the existing strong English and technical-token behavior while making Chinese substring discovery useful.

Recommended design:

- Keep readable redacted text separate from search-only normalization.
- Add deterministic CJK n-gram tokens to a dedicated search field or equivalent derived representation.
- Transform Chinese queries with the same normalization.
- Keep English token, prefix, project, title, and future metadata search behavior unchanged.
- Do not add embeddings or a new search service in v0.1.

Verification:

- Synthetic fixtures cover Chinese substrings at the start, middle, and end of continuous text.
- Mixed Chinese/English queries and technical identifiers retain expected matches.
- Existing English search tests remain green.
- Search snippets never expose unredacted text or search-only token noise.

Exit condition: the previously failing Chinese sample class passes without regressing English discovery.

### 5. Complete core TUI actions and visibility controls

Make the safe index usable for the daily Codex workflow.

Scope:

- Add an explicit “show hidden” toggle for subagent, `exec`, and unknown-source sessions.
- Keep hidden sessions excluded from default project counts and search results.
- Add `n` to start a new `codex` process in the selected project's directory.
- Keep Enter as native resume in the session's recorded directory.
- Explain unavailable or missing project paths rather than falling back silently.
- Keep temporary reveal and hidden-mode state visually obvious.

Verification:

- TUI model tests cover toggles, counts, search visibility, resume, new session, missing cwd, and cancellation.
- Executable stubs capture command arguments and actual cwd for both resume and new-session actions.
- 80x24 PTY smoke tests cover browse, search, preview, toggle, resume, and quit.

Exit condition: the primary browse → recognize → resume/new-session workflow works without external services.

### 6. Archive inherited non-Codex code in place

After behavior is safely replaced, make inherited non-Codex code unreachable without deleting or moving it. This preserves upstream reference material and makes rollback easier while avoiding a large, low-value deletion diff.

Scope:

- Remove non-Codex providers from registration and user-facing documentation.
- Remove cloud, account, analytics, telemetry, autosave markdown, Lore, and cross-agent reconstruction commands from runtime registration and navigation.
- Keep the inherited implementation packages in their existing locations as unsupported, logically archived reference code.
- Add an archive inventory documenting which packages are intentionally unreachable and why they remain.
- Do not move archived packages into a new directory; preserving their paths avoids unnecessary import churn and merge conflicts.
- Keep dependencies required to compile and test archived packages. Dependency reduction is not a v0.1 goal.
- Retain Apache-2.0 attribution and upstream history.
- Update help, README, examples, and architecture comments to describe the actual product.

Verification:

- Registry and command-tree tests prove archived providers and commands are unreachable from `csessions`.
- Network isolation tests prove archived PostHog, OTLP, SpecStory Cloud, and version-check code cannot run through supported commands.
- Documentation clearly labels archived packages as unsupported and excludes them from user workflows.
- Build and complete Go tests, including retained archived-package tests, pass from a clean module cache.

Exit condition: the binary and documentation expose one coherent Codex-only product, while inherited source remains available only as an explicitly documented implementation archive.

### 7. Run the v0.1 release gate

Validate the integrated product before tagging.

Automated gate:

- `gofmt` reports no change.
- `go vet ./...` passes.
- `go test ./...` passes without exclusions.
- A clean `go build` produces `csessions`.
- Command and registry audits prove archived non-Codex code is unreachable from the product surface.
- Synthetic security tests prove the database contains no raw sentinel secrets, reasoning, tool parameters, or tool output.
- Isolated-home tests prove no network access and no writes outside XDG paths.

Real-corpus aggregate gate:

- Run against an isolated configuration and derived database.
- Report only counts, timings, sizes, and pass/fail assertions; never print transcript text, paths containing private names, endpoints, or credentials.
- Confirm the expected interactive/background classification totals reconcile with the native files.
- Confirm incremental reindex leaves unchanged sessions untouched.
- Confirm sampled Chinese and English searches by synthetic marker or sanitized assertion.
- Confirm resume and new-session executable stubs receive the intended cwd.

Manual gate:

- Verify the TUI over SSH at 80x24.
- Verify raw reveal is clearly temporary and clears on navigation.
- Verify deleting the derived database and rerunning reindex fully recovers the application.

Exit condition: all gates pass, known limitations are documented, and `v0.1.0` can be tagged from `dev`.

## Development protocol

For every observable behavior change:

1. Start a focused TDD record.
2. Add a synthetic failing test that demonstrates the user-visible or security failure.
3. Implement the smallest coherent fix.
4. Run focused tests, relevant package tests, and then the complete suite.
5. Inspect the diff for secret-bearing fixtures, unrelated changes, generated files, and dependency drift.
6. Commit on an `agent/*` branch, push, and open a Draft PR against `9penny/codex-sessions:dev`.
7. Merge only after the PR's exit condition passes.

Documentation-only and mechanical cleanup changes do not require artificial failing tests, but still require formatting, link, diff, and build validation appropriate to their risk.

## Stop conditions

Stop the current implementation slice and reassess if any of these occur:

- A proposed feature requires persisting unredacted transcript content outside native JSONL.
- Redaction failure would allow content to be indexed, displayed by default, or sent externally.
- A command can contact the network without an explicit future-version opt-in.
- A migration could mutate or delete native Codex sessions.
- A new dependency is required without a documented benefit and explicit approval.
- Passing a test would require weakening one of the locked safety rules.

## Deferred until after v0.1

- AI title, summary, and tags
- API configuration and enrichment batching
- Embeddings and semantic search
- Manual metadata editing
- Favorites, folders, and archive-management UI
- macOS, native Windows, package-manager distribution, accounts, sync, and collaboration
