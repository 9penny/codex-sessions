# 项目会话网页

`csessions web` 是各台机器独立运行的本地会话浏览器。页面负责发现、阅读、搜索和整理历史，继续对话仍使用 Windows Terminal 中的 WSL 或 SSH 终端。

这是当前开发分支新增的功能；已发布的 v0.3.1 不含此命令。

## 启动

在仓库中构建并启动：

```bash
cd specstory-cli
go build -o bin/csessions .
./bin/csessions web
```

如果已经把新版本二进制安装到 PATH，在任意目录执行 `csessions web` 即可。

打开终端打印的完整链接，例如 `http://localhost:5431/#token=…`。WSL 下在 Windows 浏览器打开同一链接；无需切换到项目目录。链接里的临时访问令牌只对本次服务有效，页面打开后会从地址栏移除，并保存在当前标签页的会话存储中。服务重启后请使用新的链接。

默认端口为 5431。端口被占用时用 `csessions web --port 5432`，或 `--port 0` 自动选择空闲端口。Ctrl+C 停止服务。每个会话库同时只允许一个网页服务运行，避免多个进程覆盖个人整理数据。

## SSH / Tailscale

在远程机器上启动 `csessions web`。在 Windows Terminal 的 WSL 标签页中建立转发：

```bash
ssh -N -L 5431:127.0.0.1:5431 your-tailscale-host
```

然后在本机浏览器打开远程服务打印的完整 localhost 链接。`your-tailscale-host` 换成你现有 SSH 配置中的主机名、Tailscale 名称或地址。服务只监听远程机器的 loopback，不需要公开端口。

若本机端口 5431 已被其他机器的会话库占用，可使用 `-L 5432:127.0.0.1:5431`，并把浏览器链接端口改为 5432，保留原访问令牌。每台机器有自己的页面、扫描位置、收藏和标题，没有跨机器汇总或同步。

页面里的“复制终端恢复命令”生成 `cd -- '原项目目录' && codex resume '会话ID'`。把它粘贴到**会话所在机器**的 WSL / SSH 终端；浏览器不会自动连接或接管已有终端。若会话来自其他原生 Codex 存储，会在命令中设置相应的 `CODEX_HOME`。项目目录不存在时不提供恢复命令，但仍可阅读保留下来的会话文件。

## 首次扫描与后续更新

启动时先扫描当前 `CODEX_HOME/sessions`（默认 `~/.codex/sessions`），再遍历 `~/`，寻找具有 Codex 原生 `session_meta` 和用户消息的 JSONL。普通项目目录本身不保存 Codex 会话；导航目录来自会话中记录的原始工作目录。

- 扫描过程中逐步显示目录和会话，底部展示进度和无法读取的位置数量。
- 跳过符号链接，以及 `.git`、`node_modules`、`.cache`、`.venv`、`venv`、`vendor`、`.Trash` 子目录。
- 同一会话 ID 的副本只保留一个索引条目，优先使用标准 Codex 存储中的文件。备份副本可供阅读；它若不在可供 Codex CLI 发现的存储中，仅靠 ID 不一定能直接恢复。
- 可以从“扫描位置”添加 `~/其他目录` 或 `/mnt/d/…` 等绝对路径。初始范围只包括当前用户主目录和配置的 Codex 存储，不自动遍历其他用户或整块磁盘。
- 每 15 秒检查标准存储和已经发现的会话存储目录，只重新解析变化的会话。页面每 4 秒检查更新；阅读中的会话更新时保留阅读位置。
- “刷新”重新遍历所有配置的扫描位置，可发现全新位置的会话存储。
- 广泛目录扫描不会根据“没找到”删除索引条目；无权限和中断不会造成历史丢失。原生会话删除的既有 `csessions reindex` 行为仍保留。

所有扫描和预览均只读原始 JSONL。新服务与终端命令共用可重建的脱敏索引和已有 AI 元数据。

## 项目导航与搜索

左侧是目录树，默认展开主目录和 `~/Projects`。选择父目录会汇总所有子目录会话；`/work/app` 不会误包含 `/work/app-old`。目录可折叠、筛选，按名称或最近活跃排序；原目录不存在时以状态提示标出。

中间按最近更新时间显示会话。顶部搜索同时匹配所选目录下的中英文对话、AI 元数据和手动标题，结果包含正文命中片段。切换“全部项目”可跨项目搜索。列表分页显示，不会因为全局搜索结果上限而漏掉较早项目中的匹配。

右侧显示脱敏的 Markdown 对话，包括代码块、表格和复制代码按钮。搜索打开会话后自动查找对应文本，也可以在“会话内查找”输入新词，用 Enter 或向下按钮跳转。Ctrl+K 聚焦列表搜索。

后台 `subagent`、`exec` 和未知来源的会话默认不显示，可以勾选“后台会话”。

## 改标题、收藏、隐藏与恢复

显示标题优先级为：**手动标题 → 有效的 AI 标题 → 原始标题**。改标题时清空输入即可恢复自动标题，不会覆盖 AI 生成结果。

收藏后从“我的收藏”快速进入。隐藏后从“已隐藏”找回，再点“恢复显示”。这些动作只改变网页会话库的整理信息，不删除原始历史。

个人整理信息和扫描位置保存在 XDG 数据目录下的 `csessions/library.json`（默认 `~/.local/share/csessions/library.json`），采用私有权限和原子文件替换。**它是需要保留的个人数据，不是可丢弃缓存。** 删除或重建旁边的 `sessions.db` 不会删除标题、收藏和隐藏状态；重新发现相同 ID 后会重新应用。

网页也能展示、恢复既有终端 `d` 隐藏的索引条目。网页的整理状态独立于旧 TUI 的隐藏状态；网页恢复不会自动改变终端的筛选结果。

## 保留 AI 标题与摘要

已有有效 AI 标题、摘要和标签自动展示，手动标题不会覆盖它们。会话详情中的“AI 标题与摘要”提供两个可复制命令：

```bash
csessions enrich --project '/项目路径' --limit 10 --dry-run
csessions enrich --project '/项目路径' --limit 10 --yes
```

预览命令在本地计算用量；生成命令沿用已有的 AI 配置、脱敏和预算限制，为当前项目的一批会话生成元数据。父目录导航范围与此项目生成范围不是同一概念；生成命令明确使用当前打开会话所属的项目路径。生成后页面会读取更新结果。

网页不会自动调用 AI，也不会读取或显示 API 密钥。生成的标题、摘要仍是可丢弃的派生数据，与永久保留的手动整理信息分开。配置说明见 [AI enrichment 指南](V0.2-ENRICHMENT.md)。

## 验证

Go 回归测试覆盖扫描发现、增量更新、取消保护、目录边界、正文与 AI 搜索、分页、手动标题优先级、部分更新、持久化失败、隐藏恢复、HTTP 访问控制、预览脱敏及终端命令转义：

```bash
go test ./pkg/cmd -run TestWeb
go test ./...
golangci-lint run
```

可选的真实浏览器验收脚本使用独立临时 HOME、模拟会话和独立索引，不读取真实历史、不调用 AI。它验证目录导航、搜索、复制命令、整理操作、AI 展示、额外扫描位置、端口转发、服务重启和索引重建后的整理恢复。

已有 Playwright 和 Chromium 的开发环境可以运行（从仓库根目录）：

```bash
go -C specstory-cli build -o bin/csessions .
PLAYWRIGHT_MODULE=/path/to/node_modules/@playwright/test \
CHROME_PATH=/path/to/chrome \
node specstory-cli/tests/web-browser.cjs
```

也可省略环境变量，使用环境中可解析的 `@playwright/test` 与其浏览器。网页本身无需 Node、npm、外部 CDN 或前端构建步骤；HTML、CSS、JavaScript 打包在 Go 二进制中。
