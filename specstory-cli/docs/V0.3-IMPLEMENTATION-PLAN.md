# Codex Sessions v0.3 Implementation Plan

Updated: 2026-08-16

Progress: slices 1–3 implemented on the v0.3 development branch; release gate pending.

## Objective

Make the disposable session index reliably follow permanent deletions from Codex while preserving
Codex sessions as the sole source of truth and keeping csessions soft-delete behavior reversible at
the index level.

v0.3 is a focused reliability release. It addresses deletion behavior observed during real use and
clarifies the two distinct deletion operations exposed by Codex and csessions.

## Locked product decisions

- A successful complete reindex reconciles live indexed Codex sessions against the native Codex
  session inventory.
- If a live indexed Codex session is absent from that complete inventory, its derived session row,
  search data, and AI metadata are removed atomically.
- Provider load failures, enumeration errors, panics, cancellation, and incomplete scans must never
  trigger reconciliation for the affected provider.
- csessions soft-delete tombstones remain intact even when the corresponding native session is
  absent. This preserves the user's explicit choice if the native session later reappears.
- Native Codex JSONL is never changed or deleted by csessions.
- The TUI and documentation clearly distinguish Codex `/delete` (permanent native deletion) from
  csessions `d` (soft deletion from the disposable local index).
- AI pricing, token-accounting differences, and new cost controls are deferred. The existing
  explicit consent, redaction, and configured enrichment limits remain unchanged.
- Directory-tree navigation, semantic search, background enrichment, cloud features, and additional
  platform packaging remain out of scope.

## Delivery order

### 1. Complete-scan contract

- Change provider enumeration to retain an explicit success or failure result per provider.
- Treat provider load failure, returned error, recovered panic, or interrupted execution as an
  incomplete scan.
- Keep partial results usable for normal indexing, but do not use them to infer deletions.
- Add focused tests for successful, failed, panicking, and cancelled enumeration outcomes.

Exit condition: callers can prove that a provider inventory is complete before reconciling it.

### 2. Atomic stale-row reconciliation

- Add a session-index operation that accepts one provider's complete set of native session IDs.
- Remove only live rows for that provider that are absent from the complete set.
- Delete associated FTS rows and AI metadata in the same transaction.
- Preserve tombstoned rows and rows belonging to all other providers.
- Run reconciliation only after the provider scan is complete and the current indexing writes have
  succeeded.
- Report the reconciled count without exposing session IDs, paths, or transcript text.

Exit condition: deleting a native Codex session and running `csessions reindex` removes its live
derived record, while every failure path leaves existing records untouched.

### 3. Deletion UX and documentation

- Show the available `d delete` action in the local-session TUI footer.
- Show `p filter projects` wherever project filtering is available.
- Document Codex `/delete`, csessions `d`, reconciliation timing, tombstone behavior, and recovery
  boundaries in the README and resume documentation.
- Keep confirmation text explicit that csessions never deletes native files.

Exit condition: a user can predict which data each deletion action affects before invoking it.

### 4. v0.3 release gate

- Run focused regression tests, package tests, the full Go test suite, and `golangci-lint run`.
- Build the release binary and run release-contract and installer checks.
- Dogfood against a disposable synthetic Codex session: index it, remove its native fixture, reindex,
  and verify it disappears without touching unrelated live rows or tombstones.
- Inspect the diff and artifacts for credentials, native transcript content, local paths, generated
  databases, dependency drift, and unrelated inherited code.
- Merge reviewable pull requests into `dev`, publish `v0.3.0`, reinstall it locally, and repeat the
  deletion workflow with aggregate output only.

Exit condition: all gates pass, the release is published, and the installed binary reproduces the
documented behavior.

## Development protocol

For every behavior change:

1. Start a focused TDD record.
2. Add the narrowest failing regression test and confirm the failure represents the missing
   behavior.
3. Implement the smallest coherent change.
4. Run `golangci-lint run` after the code change and progressively broader tests after each slice.
5. Inspect the diff for native-data risk, secret exposure, dependency changes, and unrelated edits.
6. Use an `agent/*` branch and a draft pull request against `dev`; merge only after CI passes.

No new dependency or native-session mutation is allowed without stopping for explicit review.

## Stop conditions

Stop and reassess if:

- reconciliation can run without proof of a complete provider inventory;
- a scan error can be mistaken for an empty provider inventory;
- a tombstone or another provider's row can be removed;
- FTS or AI metadata can become orphaned;
- native Codex JSONL might be modified;
- interruption can leave a partially reconciled index;
- a new dependency appears necessary.

## Deferred until after v0.3

- AI pricing analysis, provider token-accounting investigation, and additional cost controls
- directory-tree project navigation
- embeddings and semantic/vector search
- automatic/background enrichment
- favorites, folders, archive management, and manual metadata editing
- accounts, sync, collaboration, macOS, native Windows, and package-manager distribution
