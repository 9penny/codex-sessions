# Codex Sessions v0.2.2 Release Gate

Date: 2026-08-16

Result: **PASS — ready to publish from `dev`**

This patch was prompted by dogfooding the public v0.2.1 installer on a real Linux installation.
The installed derived database had mode `0644` inside a `0755` data directory.

## Regression and migration evidence

- A test fixture explicitly reproduces legacy `0755`/`0644` permissions independently of umask.
- Before the fix, the regression test observed `0755` on the application directory and `0644` on
  `sessions.db`, `sessions.db-wal`, and `sessions.db-shm`.
- After the fix, the same test observes `0700` on the application directory and `0600` on all
  three SQLite files.
- The real default index migrated to directory mode `0700` and database mode `0600`; all 101 Codex
  sessions remained up to date.
- `go test ./...`, `go vet ./...`, `go build ./...`, formatting, and diff checks pass.

The native `~/.codex/sessions` tree remains read-only and authoritative. The migrated SQLite file
is still a disposable derived cache; the patch changes filesystem permissions only.

## TDD effect record

Bug-fix record: `20260816T051546Z-625b22ad`.

The first attempted RED run passed because the test logger itself uses umask `077`. The fixture was
then corrected to set legacy modes explicitly; it accurately failed on all four permission checks
before the implementation and passed afterward.
