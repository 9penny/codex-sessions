# Codex Sessions v0.2 Implementation Plan

Updated: 2026-08-16

Progress: slices 1-5 are merged. The slice 6 security, cost, real-corpus, clean-cache, packaging,
and installer gates pass; publication follows merge of the release report.

## Objective

Add optional, low-cost AI-generated titles, summaries, and tags to the local Codex session browser
without weakening the v0.1 privacy model. Native Codex JSONL remains authoritative and unchanged;
all AI metadata remains disposable derived data.

The work is one continuous v0.2 objective, delivered as independent pull requests so every slice
has a reviewable rollback boundary.

## Locked product decisions

- AI enrichment is opt-in and runs only through an explicit `csessions enrich` command.
- `resume`, `search`, `reindex`, `version`, TUI startup, and exit remain network-free.
- Only fail-closed redacted conversation text may enter an API request.
- Reasoning, tool arguments, tool output, native paths, session IDs, project paths, environment
  variables, credentials, and machine identifiers are excluded from requests.
- Requests use the OpenAI Responses API-compatible contract with `store: false` and no tools.
- API providers may still retain content for abuse monitoring under their own policy. The CLI must
  show this boundary before the first live request and document it permanently.
- The API key comes from `CSESSIONS_OPENAI_API_KEY` or an explicit private config file. It is never
  accepted as a command-line flag, persisted in SQLite, printed, or logged.
- A custom endpoint is opt-in through `CSESSIONS_OPENAI_BASE_URL`; redirects to a different host
  are rejected to avoid forwarding credentials.
- The default model is selected by synthetic quality/cost evaluation. Model names stay
  configurable because account availability changes.
- `gpt-5.3-codex-spark` is not assumed to be an API model: official API documentation does not
  currently list it. It may be tested only if the configured account's model endpoint exposes it.
- Enrichment is bounded by explicit session and estimated-token budgets, supports cancellation,
  and never runs automatically in the background.
- Generated title, summary, tags, model, prompt version, source fingerprint, and usage are stored
  only in the disposable XDG SQLite database.
- Embeddings and semantic/vector search remain out of scope for v0.2.

## Delivery order

### 1. Public repository and plan closeout

- Record the completed v0.1 release and link its release page.
- Replace inherited public issue forms with Codex Sessions privacy-safe bug and feature forms.
- Route current documentation to this plan and clearly label inherited plans as archived.

Exit condition: the public repository describes the shipped product and the next supported scope.

### 2. API configuration and explicit network boundary

- Add a small active configuration type separate from inherited SpecStory configuration.
- Support environment variables and a mode-0600 local config file under
  `~/.config/csessions/ai.toml` (or `XDG_CONFIG_HOME`). Environment variables win.
- Reject group/world-readable key files, non-HTTPS remote endpoints, cross-host redirects, keys in
  URLs, and unknown configuration fields.
- Add `csessions enrich --dry-run` before enabling live requests.
- Keep the runtime network-isolation regression test for every non-enrichment command.

Exit condition: only the explicit enrichment path can construct an authenticated HTTP client.

### 3. Synthetic model and endpoint evaluation

- Discover models through the configured endpoint without printing credentials or endpoint values.
- Evaluate available low-cost candidates on synthetic Chinese, English, mixed-language, technical,
  empty, and secret-shaped sessions.
- Require schema-valid title, summary, and tags; compare deterministic rubric scores, latency, and
  returned token usage.
- Prefer the cheapest candidate that passes the quality floor; record the evidence as aggregate
  results without response prose.

Exit condition: the default is evidence-based and every other passing model remains selectable.

### 4. Redacted enrichment pipeline and derived storage

- Select supported conversation messages from native JSONL on demand.
- Redact before request construction and fail closed on parsing or detector errors.
- Apply deterministic length limits after redaction and show aggregate payload sizes in dry-run.
- Request strict structured JSON: short title, concise summary, and a bounded tag list.
- Validate output sizes and characters before persisting.
- Add an `ai_metadata` table keyed by `(agent, session_id)` with source fingerprint and prompt
  version so unchanged sessions are skipped and stale results can be regenerated.
- Support `--limit`, `--max-input-tokens`, `--model`, `--force`, and cancellation.

Exit condition: interrupted reruns resume safely, and deleting the derived database removes all AI
metadata without affecting native sessions.

### 5. Search and TUI integration

- Prefer an AI title when current for the session; visually mark it as generated.
- Show the summary and tags in masked preview without replacing the native transcript.
- Index validated title, summary, and tags into the existing FTS path, including CJK normalization.
- Preserve search behavior when no AI metadata exists or metadata is stale.
- Provide a visible explanation that AI metadata is generated and may be wrong.

Exit condition: enriched metadata improves discovery while the complete v0.1 workflow remains
usable with AI entirely unconfigured.

### 6. v0.2 security, cost, and release gate

- Prove all non-enrichment commands make zero connection attempts.
- Capture synthetic HTTP requests and assert `store: false`, no tools, strict output schema, and no
  raw sentinel secrets or excluded metadata.
- Prove authentication headers are stripped on redirect and never appear in errors or logs.
- Verify session, input, output, and retry limits prevent unbounded spend.
- Run formatting, vet, lint, full tests, clean build, snapshot packaging, and installer tests.
- Run real-corpus checks using aggregate counts and sizes only; never print prompts or AI output.
- Publish `v0.2.0` only after the report is merged into `dev`.

Exit condition: all gates pass and known API data-retention limitations are documented.

## Development protocol

For every behavior change:

1. Start a focused TDD record.
2. Add a synthetic failing test at the narrowest stable boundary.
3. Implement the smallest coherent slice.
4. Run focused, package, full, lint, and release-contract checks appropriate to its risk.
5. Inspect diffs for secrets, raw transcript fixtures, endpoint values, generated output, and
   dependency drift.
6. Use an `agent/*` branch and a draft PR against `dev`; merge only after CI passes.

API evaluation is never allowed to use real transcript text. It uses synthetic fixtures and
reports only model names, pass/fail, token counts, latency, and estimated or documented price.

## Stop conditions

Stop and reassess if:

- unredacted content can reach an HTTP request, SQLite, logs, or test artifacts;
- a non-enrichment command can initiate network access;
- a redirect or endpoint parser can send a key to an unapproved host;
- enrichment can run without an explicit budget or consent;
- output parsing can persist arbitrary model prose as trusted metadata;
- native JSONL might be modified;
- a new dependency is required without an explicit benefit and review.

## Deferred until after v0.2

- embeddings and semantic/vector search
- automatic/background enrichment
- favorites, folders, archive management, and manual metadata editing
- accounts, sync, collaboration, macOS, native Windows, and package-manager distribution
